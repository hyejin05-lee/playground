아키텍처 설계, 클래스 구조화 시 항상 SOLID 원칙을 적용하세요. 필요한 추상화, 인터페이스, 의존성 주입 등을 코드에 자연스럽게 구현한다.

- SRP: 클래스가 하나의 명확한 변경 이유를 가지는가?
- OCP: 안정된 코드를 크게 수정하지 않고 변형을 추가할 수 있는가?
- LSP: 하위 타입이 상위 타입의 기대를 깨지 않고 대체 가능한가?
- ISP: interface가 역할별로 작고 명확한가?
- DIP: 상위 정책이 구체 구현보다 추상화에 의존하는가?
